# AGENTS Governance

## Purpose

This document explains the single-authority architecture for Earl's general agent governance.

```text
Context Vault AGENTS.md
        |
        +-- generated byte-identical managed replicas
        |
        +-- separate project/local extensions
```

There is one editable general-policy authority. Physical replicas exist only because Codex, project repositories, and local runtimes need an `AGENTS.md` at specific entrypoints.

## Canonical master

Logical canonical file:

```text
Repository: invicta-ctrl/gpt-context-vault
Relative path: AGENTS.md
Preferred checkout path:
D:\Documents\Codex\GitHub\gpt-context-vault\AGENTS.md
```

During implementation, the accepted candidate is prepared on:

```text
branch: governance/agents-consolidation-001
worktree:
D:\Documents\Codex\GitHub\worktrees\gpt-context-vault-agents-consolidation-001
```

The candidate becomes the active canonical master only after the Context Vault repository's accepted protected adoption path completes. Until then, live replicas remain unchanged except for separately authorized candidate branches.

A blocked target is not silently skipped and called complete. It is reported as `BLOCKED` with the exact reason.

## Project extensions

Universal rules never absorb project-specific release, runtime, model, provider, data, or local-tool details.

Registered extension path:

```text
.agents\PROJECT_POLICY.md
```

Canonical extension sources live under:

```text
governance\agents\extensions\
```

They are deployed only through the relevant target's own authority and Git or runtime workflow.

## General-policy change workflow

When a change is requested against any replica:

1. Determine whether the change is genuinely universal or project-specific.
2. Universal changes go to the Context Vault canonical master.
3. Project/local changes go to the registered extension.
4. Update the registry when a target, gate, or disposition changes.
5. Run the sync script without `-Apply`.
6. Review every `WOULD_UPDATE`, `WOULD_CREATE`, and `BLOCKED` result.
7. Confirm repository handshakes, writer locks, dirty state, and extension availability.
8. Use explicit apply mode only for eligible targets.
9. Run verification.
10. Review every touched repository diff and local backup.
11. Commit and push only through each repository's accepted path.
12. Record blockers and stop.

Never copy a modified replica back to the canonical master.

## Synchronization

Dry run:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
  -File automation\agents-governance\sync-agents.ps1
```

Candidate-branch dry run:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
  -File automation\agents-governance\sync-agents.ps1 `
  -IncludeCandidateTargets
```

Apply only after reviewing eligible targets:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
  -File automation\agents-governance\sync-agents.ps1 `
  -IncludeCandidateTargets `
  -Apply
```

Live targets remain blocked in the registry until their exact activation gates pass.

The script:

- reads the canonical root-policy bytes and the registered project-extension source bytes from the current Context Vault checkout;
- reads only registered targets;
- refuses unexpected pre-change hashes for both replica and extension;
- performs dry-run by default;
- writes replica and extension atomically;
- creates and verifies timestamped backups for eligible non-Git replica and extension files;
- never updates historical, worktree-derived, vendor, backup, test, stale, unknown, or unregistered paths.

## Verification

Candidate verification:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
  -File automation\agents-governance\verify-agents.ps1 `
  -IncludeCandidateTargets
```

Strict final verification, after all required gates pass:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
  -File automation\agents-governance\verify-agents.ps1 `
  -FailOnBlocked
```

The verifier reports:

```text
MATCH
DRIFT
MISSING
BLOCKED
```

It compares each eligible replica with the canonical root and each eligible extension with its registered extension source. It exits non-zero for drift or missing eligible replicas/extensions. `-FailOnBlocked` also treats required blocked targets as failure for final-completion checks.

## Recovery

Git-tracked policy changes are recoverable from exact pre-change commits and dedicated task branches.

Before an eligible non-Git replica changes, synchronization creates a timestamped backup and confirms its hash.

Every archived or moved policy must retain:

- original path;
- original SHA-256;
- classification;
- reason;
- replacement or compiled destination;
- rollback location.

If a unique rule is lost, a replica drifts, or an extension cannot be loaded, stop and restore the verified original state.

## Exclusions

Never synchronize or rewrite:

- HAU historical or active worktrees merely to match the master;
- immutable evidence snapshots;
- archives and recovery packages;
- temporary CodexPro fixtures;
- third-party repositories;
- package-manager caches;
- bundled plugins;
- plugin marketplaces;
- examples and backups;
- stale owned copies before preservation/reference gates pass;
- unregistered paths.
