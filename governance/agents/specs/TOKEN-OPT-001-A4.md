## Routing and execution contract

The current machine-readable profile, not the stable Markdown protocol, owns active
model assignments. It must support profile replacement without rewriting universal
governance.

```yaml
orchestrator: gpt-5.6-sol / high
writer: gpt-5.6-terra / max / one overlapping writer
worker.durable: gpt-5.6-luna / max / read_only
worker.ephemeral: openrouter/stealth/ox-alpha / high / read_only
disabled_models:
  - deepseek-v4-pro
  - deepseek/deepseek-v4-pro
```

Ox is eligible only when its provider is available, both prompt and completion
prices are zero, health is acceptable, and the requested data class is suitable.
Eligibility is evaluated at bounded cadence and cached per run/session. When Ox is
ineligible or fails, mark it ineligible for that run, fail over once to Luna using
the same worker contract, and do not enter a retry loop. The system must remain
fully usable with Ox disabled. Sol remains the high-effort parent and is disabled
as a child. Terra, Luna, and Ox may be eligible children only through their stated
contracts. DeepSeek V4 Pro aliases are disabled and absent from active and fallback
routes; unrelated DeepSeek Flash configuration is preserved.

## Context, concurrency, and delegation contract

```text
dispatch seed target: <= 12K tokens
worker working target: <= 32K tokens
normal hard ceiling: <= 64K tokens
above 64K: require OVERSIZE_CONTEXT_REASON
above 100K: split unless an explicit correctness/safety exception is recorded

default capacity: one Terra writer plus two read-only workers
normal adaptive capacity: one writer plus two to four read-only workers
Ox-free/healthy independent burst: <= 6 total active workers
overlapping writers: exactly one
recursive worker spawning: disabled by default
ordinary duplicate questions/reviews: prohibited
stop: STOP WHEN GREEN
```

This supersedes only older conflicting TOKEN-OPT defaults for model routing,
context budgets, total read-only worker capacity, fallback, and verification.
It preserves A1 unchanged: a no-auto-start next-slice pipeline, one writer,
read-only non-delegating scout semantics, ending-SHA revalidation, and the rule
that a scout never starts the next slice. The A1 scout is a specialized pipeline
rule and no longer defines the total current-slice read-only capacity.
